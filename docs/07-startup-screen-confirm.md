# Стартовый экран dev-channels: подтверждение по содержимому и проверка зависания

## Что это за экран

Плагин запускает Claude Code с флагом `--dangerously-load-development-channels server:dashi-channel`.
После перезапуска (перезагрузка, обновление Claude Code, сбой) Claude Code может остановиться на экране:

```
WARNING: Loading development channels
…
❯ 1. I am using this for local development
  2. Exit

Enter to confirm · Esc to cancel
```

Пока никто не нажал Enter, агент «глухой»: процесс жив, сервис «зелёный», а сообщения из Telegram копятся в очереди.

## Правило: никакого слепого ввода

Нельзя отправлять клавиши «по таймеру» (`sleep 6; send-keys Enter`): экран может появиться позже, а Enter попадёт в другой диалог или в рабочую сессию. Единственная автоматическая клавиша – Enter от `scripts/confirm-startup-screen.sh`, и только когда на экране именно это предупреждение.

## Как работает подтверждение

`scripts/confirm-startup-screen.sh` после старта до 90 секунд смотрит на экран (`tmux capture-pane -p`) и нажимает Enter, только если на экране ровно один диалог – именно этот. Все условия сразу:

- виден текст предупреждения dev-channels;
- на экране нет признаков никакого другого диалога (доверие к папке, внешние импорты, bypass, вход, обновление, чужая подсказка «Enter to select»);
- подсказка «Enter to confirm» на экране ровно одна, и выделенный пункт с номером ровно один;
- курсор (`❯`) стоит на пункте 1 «I am using this for local development», других курсоров в диалоге нет, третьего пункта нет;
- ниже подсказки «Enter to confirm» ничего постороннего.

Текст выше предупреждения (строка запуска в shell, сообщения системы) разрешён. Само имя флага `--dangerously-load-development-channels` в строке запуска предупреждением не считается. Если хоть одно условие не выполнено – вид экрана `dev-channels-unrecognized`, код 4, ничего не нажато.

После нажатия скрипт проверяет, что экран исчез. Нажатий не больше двух. Срок (`--timeout`) проверяется на каждом круге и перед каждым нажатием; `--timeout 0` – это один взгляд без нажатия. Если сессия уже работает, скрипт выходит с кодом 0 и ничего не нажимает. Любой другой экран (доверие к папке, вход, обновление, внешние импорты `CLAUDE.md`, обычная строка ввода) он только называет в логе.

Сессия без входа в аккаунт показывает обычную строку ввода и надпись «Not logged in · Please run /login». Такой экран считается `login`, а не `ready`: клавиш он не получает, а проверка зависания поднимает по нему оповещение.

### Чтобы Enter не попал в другой экран

- Цель (`имя сессии`) один раз переводится в номер панели tmux (`%N`), и все взгляды и нажатие идут по этому номеру: переименование сессии или смена активной панели нажатие не перенаправят.
- На одну панель – один подтверждающий процесс. На время работы скрипт создаёт каталог-замок в `~/.local/state/dashi-startup-screen/locks` (переменная `STARTUP_CONFIRM_LOCK_DIR`). Второй процесс на той же панели выходит с кодом 8 и ничего не нажимает. Замок процесса, которого уже нет, считается брошенным и забирается.
- Перед самым нажатием скрипт смотрит на экран ещё раз, без паузы между взглядом и клавишей.

**Остаточный риск (принят, tmux его закрыть не даёт).** Взгляд на экран и нажатие – две отдельные команды tmux. Если Claude Code сменит диалог за несколько миллисекунд между последним взглядом и клавишей, Enter попадёт в новый экран. Замок убирает из этого окна другие подтверждающие процессы, но не сам Claude Code и не человека, который печатает в панели.

Коды выхода:

| Код | Что значит |
|---|---|
| 0 | сессия у обычной строки ввода, либо диалог исчез после нашего Enter (второе – не доказательство готовности: на экране что-то нераспознанное) |
| 2 | ошибка в аргументах |
| 3 | экран dev-channels остался: после двух нажатий либо время вышло раньше, чем можно было нажать |
| 4 | предупреждение dev-channels в незнакомом виде или вместе с признаками второго диалога – ничего не нажато |
| 5 | показан другой стартовый диалог (в том числе сессия без входа) – ничего не нажато |
| 6 | за отведённое время ничего не распознано – ничего не нажато |
| 7 | tmux-сессия или панель недоступна |
| 8 | панель уже занята другим подтверждающим процессом (или замок не удалось взять) – этот запуск ничего не нажал |
| 9 | программа `tmux` не найдена (`TMUX_BIN` / `PATH`) |
| 10 | только для `--classify`: экран dev-channels, который был бы подтверждён |

Код 0 по второй причине («диалог исчез») не означает, что агент готов. Готовность – это `ready` от `--classify` или тишина периодической проверки.

### tmux не найден

Под launchd и в неинтерактивном ssh в `PATH` нет каталога Homebrew (`/opt/homebrew/bin` на Apple Silicon, `/usr/local/bin` на Intel), поэтому `tmux` «не существует». Раньше это выглядело как «нет сессии»; теперь это отдельная строка в логе (`tmux-not-found`) и отдельный код: 9 у `confirm-startup-screen.sh`, 3 у `check-startup-screen.sh`. Укажите путь явно: переменная `TMUX_BIN=/opt/homebrew/bin/tmux` (узнать путь: `command -v tmux` в обычном терминале) либо каталог в `PATH`. Wrapper из `./install.sh` уже передаёт скрипту свой полный путь к tmux; в образце `examples/startup-screen-check.plist.example` заданы и `PATH`, и `TMUX_BIN`.

В лог попадает одна строка на действие: время, цель, действие, вид экрана и имя сработавшего шаблона. Текст экрана в лог не пишется – на экране бывает личная переписка.

Фразы, по которым узнаётся экран, собраны в одном месте – в начале `scripts/confirm-startup-screen.sh` – и переопределяются переменными окружения с теми же именами (`STARTUP_PAT_DEVCH_WARNING`, `STARTUP_PAT_DEVCH_OPTION`, `STARTUP_PAT_CONFIRM_HINT` и другие). Если в новой версии Claude Code текст изменился, скрипт перестанет нажимать (код 4), а не нажмёт наугад.

Посмотреть, как скрипт видит экран сейчас, ничего не нажимая:

```bash
bash scripts/confirm-startup-screen.sh --classify -L channel-myagent channel-myagent
# печатает одно слово: ready, dev-channels, dev-channels-unrecognized, trust-folder, external-imports,
# bypass-permissions, login, update, other-dialog, unknown, no-session или tmux-missing
```

## Установка

**Новая установка.** `./install.sh` уже создаёт wrapper из `examples/launchd-wrapper.sh.example`: он запускает в tmux обычный shell, вводит в него команду запуска Claude Code и в фоне вызывает `confirm-startup-screen.sh`. Этот wrapper общий для launchd (macOS) и systemd (Linux).

**Существующий агент** (wrapper правился руками):

1. Обновите репозиторий плагина (`./update.sh`) – появятся `scripts/confirm-startup-screen.sh` и `scripts/check-startup-screen.sh`. Если плагин лежит отдельно, скопируйте эти два файла рядом друг с другом.
2. В wrapper агента, сразу после строк, которые запускают Claude Code в tmux, добавьте одну строку (сокет и имя сессии – как в самом wrapper):

   ```bash
   TMUX_BIN=/opt/homebrew/bin/tmux /bin/bash /path/to/dashi-plugin-claude-code/scripts/confirm-startup-screen.sh -L channel-myagent channel-myagent &
   ```

   `TMUX_BIN` – полный путь к tmux на этой машине (`command -v tmux`); под launchd без него скрипт tmux не найдёт (код 9).

3. Удалите из wrapper блок со слепыми нажатиями (`sleep 6` … `send-keys … Enter`), если он есть.
4. Подключите периодическую проверку (следующий раздел).

Новый wrapper начнёт работать со следующего перезапуска агента; перезапускать агента специально не нужно.

## Проверка зависшего экрана

`scripts/check-startup-screen.sh` – разовая проверка для запуска раз в минуту. Она ничего не нажимает. Для каждого агента из списка она смотрит на экран и, если стартовый диалог виден дольше порога (по умолчанию 120 секунд), один раз на инцидент запускает команду оповещения. Когда экран исчез, состояние сбрасывается, и следующий инцидент даст новое событие.

Список агентов – файл, по строке на агента (образец: `examples/startup-screen-check.agents.example`):

```
myagent -L channel-myagent channel-myagent
```

Два запуска проверки одновременно не дадут двух оповещений: чтение состояния, оповещение и запись идут под замком на агента (`<state-dir>/<агент>.lock`); запуск, заставший замок, этого агента пропускает. Файл состояния заменяется целиком (временный файл и `mv`). Если состояние не удалось сохранить, запуск завершается с кодом 1 – иначе следующее оповещение пришло бы повторно незаметно. Испорченное время в файле состояния (например `08`) сбрасывает отсчёт, а не ломает проверку. Коды выхода проверки: 0 – порядок, 1 – не доставлено оповещение, не сохранено состояние или неверная строка агента, 2 – ошибка в аргументах, 3 – не найден `tmux`.

Оповещение – команда в переменной `STARTUP_ALERT_CMD`. Она получает имя агента, вид экрана и число секунд как `$1 $2 $3` (и как `STARTUP_ALERT_AGENT`, `STARTUP_ALERT_KIND`, `STARTUP_ALERT_SECONDS`). Если команда завершилась с ошибкой, следующая проверка попробует ещё раз. Без `STARTUP_ALERT_CMD` событие только пишется в лог.

Готовый образец команды – `examples/startup-alert.sh.example`: он сообщает агенту-наблюдателю (в образце – `arthas`) через его `webhook-listener` из этого репозитория (адрес и файл с токеном задаются переменными окружения) либо, если адрес не задан, дописывает строку в файл. Свой транспорт подключается заменой тела этого скрипта.

Запуск по расписанию:

- macOS: `examples/startup-screen-check.plist.example` (launchd, `StartInterval` 60 секунд; в нём явно заданы `PATH` с `/opt/homebrew/bin` и `TMUX_BIN`);
- Linux: `examples/startup-screen-check.service.example` и `examples/startup-screen-check.timer.example` (systemd timer).

## Как проверить, не трогая живого агента

На отдельном tmux-сокете с выдуманной сессией:

```bash
tmux -L startup-test new-session -d -s startup-test /bin/bash
tmux -L startup-test send-keys -t startup-test -l "clear; printf 'WARNING: Loading development channels\n\n❯ 1. I am using this for local development\n  2. Exit\n\nEnter to confirm · Esc to cancel'; read -r _; clear; echo 'Listening for channel messages'; sleep 600"
tmux -L startup-test send-keys -t startup-test C-m

bash scripts/confirm-startup-screen.sh --classify -L startup-test startup-test   # dev-channels
bash scripts/confirm-startup-screen.sh --timeout 20 -L startup-test startup-test # нажмёт Enter один раз, код 0
bash scripts/confirm-startup-screen.sh --classify -L startup-test startup-test   # ready

tmux -L startup-test kill-server
```

Автоматические тесты (поддельный `tmux`, настоящий не нужен): `python3 -m pytest tests/test_startup_screen_scripts.py`. Экраны dev-channels, доверия к папке, рабочей сессии и сессии без входа в тестах – настоящие снимки Claude Code 2.1.323 из `tests/fixtures/startup-screen/`.

## Как выключить

- Подтверждение: `STARTUP_CONFIRM_DISABLE=1` в окружении сервиса агента либо удалите строку вызова из wrapper. Диалог тогда подтверждает человек, посмотрев на экран. Брошенный каталог-замок (после аварийного завершения) удалять не нужно: следующий запуск заберёт его сам.
- Проверку зависания: выгрузите периодическое задание (`launchctl bootout …` / `systemctl disable --now startup-screen-check.timer`).
