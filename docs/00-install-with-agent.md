# Установка через агента — рекомендуемый путь

Откройте Codex или Claude Code на своём компьютере и передайте ему промпт ниже.
Агент подключится к серверу, проверит зависимости, установит плагин и проверит
запуск. Ручные шаги: вход в Claude (если ещё не выполнен), ввод токена бота и
на Linux без root — `sudo loginctl enable-linger USER`, если lingering выключен.
Wrapper сам принимает стартовые подтверждения Claude в автономном профиле.
На своём Mac можно работать локально, без SSH. Ручные инструкции остаются отдельно:
[Linux](03-installation-linux.md) · [macOS](03-installation-macos.md).

## Что подготовить

- Linux-сервер с systemd или Mac с macOS и доступом в интернет. Для удалённой
  установки нужны адрес, SSH-пользователь и уже настроенный доступ с вашего
  компьютера. Работайте под непривилегированным пользователем будущего агента;
  пароль и приватный SSH-ключ в чат не отправляйте. На Linux без root может понадобиться
  один раз выполнить `sudo loginctl enable-linger USER`. На macOS LaunchAgent работает после входа этого
  пользователя в графическую сессию, в том числе после перезагрузки.
- Учётную запись с доступом к Claude Code. Вход, если нужен, вы пройдёте в терминале
  сервера сами; установка плагина не предоставляет подписку.
- Telegram-бота: откройте [@BotFather](https://t.me/BotFather), отправьте `/newbot`,
  выберите имя и username, сохраните выданный токен у себя. Токен не вставляйте
  в промпт, чат с агентом или команду с открытым значением.
- Свой **числовой Telegram user ID**: напишите [@userinfobot](https://t.me/userinfobot)
  и возьмите число из поля `Id`. Нужен ваш положительный ID, а не `@username`,
  ID бота или ID группы. Этот ID даст доступ к вашему боту.
- Имя агента, например `myagent` (начинается с маленькой латинской буквы,
  дальше допустимы `a-z`, `0-9`, `_`, `-`), и абсолютный путь workspace на сервере,
  например `/home/student/.claude-lab/myagent/.claude` или
  `/Users/student/.claude-lab/myagent/.claude`.

Токен вы введёте **сами на сервере** скрытым вводом в переменную
`TELEGRAM_BOT_TOKEN`. Чтобы установщик получил эту переменную, агент организует
общую постоянную Bash-сессию в tmux. Новый SSH-вызов или соседний терминал
не наследует переменную из вашей сессии. Установщик сохранит токен только в
приватный `channel.env` с правами `600`; агенту не нужно читать значение.

## Один промпт для Codex или Claude Code

Замените пять полей в начале и вставьте весь блок. Для своего Mac в поле
«Подключение» напишите «локально». Токен сюда не добавляйте.

```text
Установи dashi-plugin-claude-code через установщик репозитория и доведи канал до
проверки реальным сообщением в Telegram.

Подключение: <SSH-адрес или локально>
Пользователь сервера: <непривилегированный пользователь>
Имя агента: <myagent>
Workspace: <абсолютный путь на сервере>
Мой числовой Telegram user ID: <положительное число>

1. Подключись к указанному серверу под указанным пользователем (или работай
локально). Проверь ОС, пользователя, доступность claude, bun, tmux и git,
версии claude --version, bun --version, tmux -V, git --version. Используй требования
актуального install.sh и scripts/lifecycle-common.sh: сейчас Claude >=2.1.0
(README рекомендует >=2.1.80), Bun >=1.3.9. Если зависимость отсутствует, покажи
точную подсказку установщика для этой ОС. Если нужны sudo, пароль, браузер или
интерактивная установка, остановись и попроси меня выполнить этот шаг в терминале.
Не запускай весь установщик от root. Если VPS доступен только как root,
сначала создай обычного пользователя с домашним каталогом (например,
useradd -m -s /bin/bash agentctl), затем работай в его login-сессии (su - agentctl).
Workspace и клон должны находиться под домашним каталогом этого пользователя;
проверку зависимостей и установку выполняй от него. Канал никогда не запускается
под root: Claude запрещает bypassPermissions с UID 0. Без --run-as USER
установщик под root останавливается до записи и показывает оба пути: создать пользователя
и повторить запуск от него либо на Linux передать существующего пользователя
через --run-as USER. На macOS root запрещён, нужен вход обычного пользователя.

2. Создай workspace и клонируй в него
https://github.com/qwwiwi/dashi-plugin-claude-code.git
в подкаталог dashi-plugin-claude-code. Если каталог уже существует, сначала
проверь его происхождение и состояние; не затирай существующие файлы. Прочитай
./install.sh --help, сам install.sh и подсказки зависимостей. Не придумывай флаги.
Согласуй фактические абсолютные пути с указанным workspace.

3. Создай отдельную постоянную Bash-сессию tmux для установки с именем
setup-<имя агента>, не используя уже занятую сессию. Дай мне точную команду
подключения к ней на сервере: tmux attach -t setup-<имя агента>.
Если Claude ещё не авторизован, остановись и попроси меня запустить claude в этой
сессии именно под пользователем агента, пройти вход /login, затем выйти из
Claude обратно в Bash. Авторизация root не заменяет авторизацию этого
пользователя. Не проходи авторизацию за меня. Стартовые подтверждения автономный wrapper принимает сам.

4. В этой же Bash-сессии я сам выключу трассировку и выполню скрытый ввод:
  set +x
  read -r -s -p 'Telegram bot token (hidden): ' TELEGRAM_BOT_TOKEN
  printf '\n'
  export TELEGRAM_BOT_TOKEN
Покажи мне эти команды без значения токена. Попроси после ввода отсоединиться
от tmux через Ctrl-B, затем D, и сообщить «готово». Пока я ввожу токен, не снимай
содержимое терминала. Не проси токен в чате, не читай его из файлов, не печатай
переменную или окружение, не используй set -x, env, printenv или tmux
show-environment для просмотра секретов. При необходимости проверяй только
наличие переменной через test -n, без вывода значения. Не просматривай
окружение процессов или состояние сервера tmux ради поиска токена.

5. После моего сообщения выполни установку именно в этой постоянной Bash-сессии,
где уже экспортирован TELEGRAM_BOT_TOKEN. Через tmux send-keys можно передать
только несекретную команду, не значение токена. Из корня клона запусти:
  ./install.sh --non-interactive --agent <имя агента> --workspace <абсолютный workspace> --owner-id <мой числовой ID> --start
Подставь реальные значения с корректным shell-экранированием путей. Токен
установщик берёт только из TELEGRAM_BOT_TOKEN; не передавай --bot-token и не
добавляй токен в аргументы. После попытки установки удали переменную из этой
Bash-сессии командой unset TELEGRAM_BOT_TOKEN. Не выводи channel.env: для
следующего запуска сервис сам прочитает его. Не считай код выхода установщика
доказательством, что канал готов: изучи итог doctor и состояние сервиса.

6. На Linux при выбранном пути от обычного пользователя установщик сам
регистрирует и включает unit в ~/.config/systemd/user через systemctl --user.
Альтернативный root-запуск только с --run-as USER создаёт системный unit в
/etc/systemd/system с User=/Group= указанного непривилегированного пользователя;
HOME и пути по умолчанию берутся из его домашнего каталога через getent.
Checkout и workspace должны быть доступны этому пользователю для чтения и записи;
при отказе покажи точную команду chown из подсказки, не меняй владельца клона молча.
С --start установщик также запускает сервис и никогда не вызывает sudo.
Если lingering выключен, покажи единственную напечатанную команду
sudo loginctl enable-linger USER и попроси меня выполнить её; скажи явно, что
до этого сервис не переживёт выход пользователя. Не выполняй sudo за меня.
Если нет user bus, установщик печатает ручные команды и завершает работу с
ненулевым кодом: покажи незавершённую установку, восстанови полноценную сессию
пользователя и повтори запуск. На macOS --start регистрирует и запускает
LaunchAgent; проверь его в GUI-сессии указанного пользователя. Wrapper сам
принимает стартовые подтверждения Claude. Если требуется именно вход в Claude,
остановись и дай мне tmux attach -t channel-<имя агента> для авторизации.

7. После запуска проверь systemd/launchd и tmux-сессию. Повтори read-only doctor
из корня клона, явно указав созданные установщиком файлы. Для стандартных путей:
  bun skills/doctor-dashi-plugin/scripts/doctor.ts --plugin-dir "$PWD/plugin" --settings "<workspace>/.claude/settings.json" --mcp "$HOME/.claude/channels/<имя агента>/channel.mcp.json" --env "$HOME/.claude/channels/<имя агента>/channel.env" --env-loader shell --user <мой числовой ID> --chat <мой числовой ID> --session channel-<имя агента> --no-autodetect
Подставь реальные значения; если пути отличаются, возьми их из несекретного
install.json. Не маскируй FAIL/WARN как успех. Покажи короткую сводку:
сервер и пользователь, commit репозитория, workspace/state/settings, имя
сервиса и tmux-сессии, состояние старта, итог doctor, что осталось сделать.
Секреты, содержимое env и полные логи с возможными секретами не показывай.
Попроси меня написать своему боту в Telegram и подтвердить получение ответа.
Без подтверждённого ответа обозначь доставку как непроверенную.

8. Оставь точный путь к клону и команду для дальнейшего обновления ./update.sh.
Объясни, что update.sh запрещает любой запуск под root до Git/Bun: обновлять
нужно от пользователя сервиса (при необходимости sudo -iu USER, затем cd в клон),
из отдельного терминала сервера, не через
обновляемый Telegram-канал; рестарт выполняется отдельно по выведенной команде.
Не выполняй обновление или лишние изменения в рамках первой установки.
```

Установщик сам проверяет зависимости, создаёт config/env, устанавливает зависимости
плагина и обычные hooks, готовит сервис и запускает doctor. Приватные config/env
при повторном запуске сохраняются, заменяемые файлы получают копии с датой.
Предустановленный профиль даёт Claude автономное выполнение действий
(`bypassPermissions`); используйте отдельный workspace и пользователя с нужными
ему правами. Не выдавайте доступ к секретам других проектов.

## Как проверить результат

Откройте своего бота по username, нажмите «Start» и отправьте обычное сообщение,
например «Ответь: связь работает». Дождитесь ответа именно в Telegram с вашего
разрешённого аккаунта. Если ответа нет, вернитесь в исходный Codex/Claude Code
и попросите проверить итог doctor, сервис и tmux: не пытайтесь чинить канал
через него самого. Успешный старт сервиса без ответа бота ещё не подтверждает связь.

## Как обновлять позже

В отдельном терминале того же сервера, под тем же пользователем, перейдите в
сохранённый агентом каталог клона и выполните:

```bash
./update.sh
```

Запуск под root обновление отклонит до Git/Bun, даже для установки с `--run-as`.
Если вы вошли как root, сначала переключитесь через `sudo -iu USER` на пользователя
сервиса и перейдите в клон. Изменённый checkout обновление отклонит и покажет мешающие файлы. Скрипт создаёт
резервные копии, обновляет код через `git pull --ff-only`, устанавливает зависимости,
проверяет тесты и hooks, затем запускает doctor с `--check-latest`. Перезапуск
по умолчанию не выполняется: используйте точную команду из результата;
для Linux user unit это `systemctl --user restart channel-myagent.service`, для
системного unit — `systemctl restart channel-myagent.service` от root (или с sudo
администратора). Если в команде есть `sudo`, выполните её сами. После рестарта
снова напишите боту.
Для нескольких агентов или нестандартного state-каталога передайте сохранённый
путь: `./update.sh --state-dir /absolute/path/to/state`.
