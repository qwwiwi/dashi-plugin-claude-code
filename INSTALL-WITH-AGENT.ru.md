# Установка с помощью агента

Вы помогаете пользователю установить Telegram-плагин на сервер Linux. Пользователь может не разбираться в технике. Объясняйте действия простыми словами. Идите по шагам и ждите, когда пользователь выполнит свою часть. В примерах имя агента — `myagent`. Команды на сервере выполняйте от отдельного пользователя без прав root, если не указано иное. Для macOS используйте [инструкцию для macOS](docs/03-installation-macos.md).

## Безопасность

- Не просите, не выводите, не копируйте и не записывайте пароли, коды OAuth, токены ботов, приватные ключи и файлы с секретами. Не просите прислать их в чат агента. Пользователь вводит их сам в своём терминале или браузере. Не используйте терминал, который записывает ввод или сессию.
- Перед каждым `sudo` объясните действие и спросите разрешение. Не выполняйте разрушительные команды. Не отключайте файрвол или permission gate без прямой просьбы пользователя.
- **До установки:** `install.sh` создаёт автономный сервис с параметром Claude `--permission-mode bypassPermissions` и обычными hooks, без включения permission gate. Claude сможет выполнять действия без обычных подтверждений. Объясните это и получите явное согласие до запуска установщика или сервиса. Если пользователь хочет подтверждения, остановитесь и используйте описание permission gate в [README](README.ru.md), согласовав настройки; не отключайте защиту молча.
- Устанавливайте и обслуживайте сервис через SSH, а не через изменяемый Telegram-канал. Не отправляйте сырые логи и содержимое терминала в чат без проверки на секреты.

## 1. Выберите сервер

**Спросите:** Есть ли сервер Ubuntu, его публичный адрес и доступ по SSH? Если нет, предложите VPS с Ubuntu 22.04 или 24.04, 2 vCPU и 2–4 ГБ RAM. Выберите регион, где доступен Claude, например Нидерланды, Германию или Финляндию. Не рекомендуйте Россию, Китай и другие неподдерживаемые регионы. До покупки проверьте текущий [список стран](https://www.anthropic.com/supported-countries). [VDSina](https://vdsina.com/?partner=6x47zemriu8q) — партнёрская ссылка; подойдёт и другой провайдер. Пользователь сам оплачивает сервер и хранит данные доступа.

**Команда:** Пока сервера нет, команд не требуется. **Проверка:** Узнайте адрес, имя SSH-пользователя и порт, но не пароль и не приватный ключ. **При ошибке:** Предложите обратиться в поддержку провайдера или использовать его консоль. Не меняйте файрвол без просьбы пользователя.

## 2. Подключитесь и перейдите на отдельного пользователя

**Спросите:** Доступен ли SSH и выполняется ли вход под root? Попросите пользователя сверить отпечаток сервера с данными провайдера. На компьютере пользователя выполните или дайте ему команду, заменив обозначения на реальные данные:

```bash
ssh -p PORT USER@SERVER
```

Если вход выполнен под root и подходящего обычного пользователя нет, спросите разрешение на создание. В оболочке root выполните `useradd -m -s /bin/bash agentctl`; обычному администратору потребуется разрешение на `sudo useradd -m -s /bin/bash agentctl`. Помогите пользователю настроить SSH-доступ к этой учётной записи способом провайдера. Не копируйте приватные ключи. Убедитесь, что позже администратор сможет выполнить команды регистрации сервиса. Подключитесь под новой учётной записью или, с разрешения, выполните `sudo -iu agentctl` из учётной записи администратора.

**Проверка:** `id -un` показывает отдельного пользователя, а не `root`. **При ошибке:** Решите проблему SSH или sudo с пользователем и провайдером. Не продолжайте от root и не ослабляйте защиту SSH.

## 3. Установите зависимости

**Спросите:** Можно установить недостающие программы? Перед `sudo` спросите отдельно. Для Git и tmux в Ubuntu:

```bash
sudo apt-get update
sudo apt-get install git tmux
```

От обычного пользователя для недостающих Claude Code и Bun установщик предлагает официальные команды:

```bash
curl -fsSL https://claude.ai/install.sh | bash
curl -fsSL https://bun.sh/install | bash
```

**Проверка:** Выполните `claude --version`, `bun --version`, `tmux -V` и `git --version`. Установщик требует Claude 2.1.0+ и Bun 1.3.9+; README рекомендует Claude 2.1.80+, а инструкция Linux — Bun 1.3.14+. **При ошибке:** Прочитайте ошибку, при изменении PATH откройте новую оболочку и следуйте подсказкам установщика. Если зависимость недоступна, остановитесь.

## 4. Разместите плагин на сервере

**Спросите:** Есть ссылка на репозиторий или архив? Для Git от пользователя сервиса:

```bash
mkdir -p "$HOME/.claude-lab/myagent/.claude"
cd "$HOME/.claude-lab/myagent/.claude"
git clone https://github.com/qwwiwi/dashi-plugin-claude-code.git
cd dashi-plugin-claude-code
```

Для архива попросите пользователя загрузить его через средство передачи файлов провайдера или `scp` со своего компьютера. Узнайте путь на сервере, сначала проверьте список файлов архива, затем распакуйте только доверенные файлы в workspace выше. Для доверенного `.tar.gz` с одной папкой репозитория пользователь может загрузить архив со своего компьютера командой `scp -P PORT /path/to/plugin.tar.gz USER@SERVER:~/plugin.tar.gz`. На сервере проверьте список через `tar -tzf "$HOME/plugin.tar.gz"`, затем выполните `tar -xzf "$HOME/plugin.tar.gz" -C "$HOME/.claude-lab/myagent/.claude"` и перейдите в корень распакованного репозитория. Убедитесь, что пути из списка остаются внутри целевой папки и не перезаписывают существующие файлы. Архив без истории Git не обновляется через `update.sh`; позже используйте чистый Git-клон и согласуйте перенос с пользователем.

**Проверка:** В корне репозитория должна успешно выполниться команда `test -f install.sh && test -f update.sh && test -d plugin`. **При ошибке:** Проверьте загрузку, структуру архива или ошибку клонирования. Не продолжайте с неполными файлами.

## 5. Войдите в Claude

**Спросите:** Есть ли у пользователя подписка Claude с доступом к Claude Code? Пользователь сам запускает `claude` в своём приватном SSH-терминале от пользователя сервиса и проходит OAuth подписки в браузере. Пароль, коды и ссылки для входа агенту не передаются. После входа выйдите из Claude.

**Проверка:** Попросите пользователя подтвердить успешный вход. Не открывайте файлы с учётными данными. **При ошибке:** Пусть пользователь следует подсказкам CLI или обратится в поддержку, затем повторит вход приватно.

## 6. Создайте бота Telegram

**Спросите:** Попросите пользователя создать бота через [@BotFather](https://t.me/BotFather), сохранить токен в тайне и узнать числовой Telegram ID через [@userinfobot](https://t.me/userinfobot). Попросите только числовой ID и имя бота. Токен пользователь введёт сам в скрытый запрос установщика в своём терминале, не в чат агента и не в записываемую сессию.

**Команда:** Не требуется. **Проверка:** ID — положительное целое число; у пользователя есть имя и токен бота. **При ошибке:** Повторите шаги BotFather или бота для получения ID. Если токен раскрыт, попросите пользователя приватно отозвать и заменить его через BotFather.

## 7. Установите, запустите и проверьте

**Спросите:** Подтвердите согласие с предупреждением об автономных правах выше, имя `myagent`, абсолютный путь workspace и разрешение на регистрацию сервиса через sudo. Пример пути: `/home/USERNAME/.claude-lab/myagent/.claude`, где вместо USERNAME указано реальное имя пользователя. Попросите пользователя выполнить в своём приватном интерактивном SSH-терминале из корня репозитория:

```bash
./install.sh
```

Пользователь вводит `myagent`, абсолютный путь workspace, числовой Telegram ID и затем токен в скрытом запросе. Не используйте флаг токена, переменную окружения, чат или запись терминала. Установщик запустит doctor и выведет точные команды регистрации в Linux. После согласия на каждое действие sudo попросите пользователя выполнить напечатанные команды, затем запустить сервис из отдельного SSH-терминала:

```bash
sudo systemctl start channel-myagent.service
sudo systemctl status channel-myagent.service --no-pager -l
```

**Проверка:** Из корня репозитория выполните `bun skills/doctor-dashi-plugin/scripts/doctor.ts`. Изучите результат, не передавая секреты. Пользователь отправляет боту личное тестовое сообщение и подтверждает ответ. **При ошибке:** Исправьте ошибки doctor, проверьте статус и логи ниже. Возможно, нужно ответить на первый запрос Claude в `tmux attach -t channel-myagent` (выход без остановки: Ctrl-b, затем d). Не отправляйте содержимое терминала с секретами. После ошибки установки исправьте её и повторите установку приватно; существующие config и env сохраняются, поэтому новый токен не заменит старый автоматически.

## 8. Обновление и остановка

**Спросите:** Пользователь хочет обновить или остановить сервис? Для обновления нужен чистый Git-клон и сеть. `update.sh` сохраняет резервные копии настроек, получает изменения, устанавливает зависимости, запускает тесты и печатает команду перезапуска. При ошибке откат выполняет разрушительную команду `git reset --hard`. По правилу безопасности этой инструкции агент не должен запускать обновление сам. Сообщите об этом до того, как пользователь самостоятельно решит, запускать ли `./update.sh` из корня репозитория в отдельном SSH-терминале. Если установок несколько, используйте напечатанную установщиком команду с `--state-dir`. После успешного обновления пользователь может согласовать и выполнить напечатанную команду перезапуска в отдельном терминале, затем повторить тестовое сообщение.

Для остановки спросите разрешение на sudo и выполните через SSH:

```bash
sudo systemctl stop channel-myagent.service
sudo systemctl status channel-myagent.service --no-pager -l
```

**Проверка:** После остановки статус показывает inactive. Остановка не отключает запуск при загрузке. Логи находятся в системном журнале: `journalctl -u channel-myagent.service -n 200 --no-pager`; для доступа может понадобиться согласованный sudo. В логах могут быть секреты. **При ошибке:** Проверьте имя сервиса и очищенный от секретов вывод статуса и doctor. После ошибки обновление могло откатиться; изучите очищенный вывод до дальнейших действий.
